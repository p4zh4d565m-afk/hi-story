# Obsidian 单向读取 MVP 设计

## 范围与数据归属

- Obsidian 主存：人物、世界观、长期大纲。
- SQLite 主存：正文、章节历史、创建正文时冻结的章纲快照、运行期事实、伏笔、AI 会话和程序状态。
- 本阶段只允许 Obsidian → hi-story 读取；不监听、不修改、不创建 Obsidian 文件，也不删除或迁移现有 SQLite 模块。

## 架构

项目表新增可选 `obsidian_path`。主进程通过独立 IPC 选择目录，并用只读扫描器递归读取 Markdown；扫描结果与核心 SQLite 项目数据分开加载，目录缺失和文件错误只形成状态或警告。渲染端用项目 ID 与请求代次隔离结果，提供一个“Obsidian 资料”只读面板用于配置、刷新和浏览。

扫描器识别 `人物/`、`世界观/`、`大纲/`（同时兼容 `characters/`、`world/`、`outlines/`），优先使用 frontmatter 的 `type` 分类和 `name` 命名；缺少 frontmatter 时用目录分类和文件名。隐藏目录、附件目录、符号链接与非 Markdown 文件不读取；单文件读取或 YAML 解析失败时跳过并记录警告。

## AI 上下文

扫描结果作为独立的“Obsidian 只读主资料”上下文块进入聊天、写章和审稿。统一构建器按文档和总 token 预算截断，只发送少量人物、世界观和长期大纲摘录；与旧 SQLite 资料冲突时提示 AI 优先参考 Obsidian，运行期事实仍以 SQLite 为准。

## 错误与兼容

- 未配置：显示配置提示，旧功能照常工作。
- 路径不存在或不可访问：显示清楚状态，项目仍成功加载。
- 单文件损坏：显示警告，其他文件继续出现。
- 快速切换项目：旧项目扫描成功或失败均不能写入当前项目状态。

## 验收

自动测试覆盖正常扫描、YAML frontmatter、无 frontmatter、路径不存在、损坏隔离、项目切换竞态、项目路径持久化和 AI 预算；生产构建通过，只读面板可配置并浏览来源明确的内容。
