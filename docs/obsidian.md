# Obsidian 单向读取使用说明

## 数据归属

| 数据 | 主要编辑与保存位置 |
| --- | --- |
| 人物、世界观、长期大纲 | Obsidian Markdown |
| 正文、章节历史、章纲快照 | hi-story SQLite |
| 运行期事实、伏笔 | hi-story SQLite |
| AI 会话、程序状态 | hi-story SQLite 的归属范围；现有 localStorage 数据待后续专项迁移 |

本阶段只有 **Obsidian → hi-story** 单向读取。hi-story 不会创建、修改或删除仓库中的任何文件，也不会把原有人物、世界观或大纲数据回写到 Obsidian。

## 最小目录规范

在一个 Obsidian 仓库或小说项目目录中建立以下目录：

```text
小说项目/
├─ 人物/
│  └─ 林砚.md
├─ 世界观/
│  └─ 灵脉规则.md
└─ 大纲/
   └─ 长期大纲.md
```

也支持英文目录 `characters/`、`world/`、`outlines/`。扫描会忽略隐藏目录、Obsidian 配置目录、附件/图片目录、符号链接和非 Markdown 文件。

模板位于 `resources/obsidian-templates/`。文件可不写 frontmatter，此时名称取文件名、类别取所在目录。推荐格式：

```yaml
---
type: character
name: 林砚
tags: [主角, 剑修]
---
```

`type` 可用 `character`、`world`、`outline`（也兼容人物、世界观、大纲）。frontmatter 会覆盖目录类别。单个文件编码或 YAML 损坏时，该文件会被跳过，其他资料继续读取。

## 配置与浏览

1. 在 hi-story 中选择小说项目。
2. 点击左上角的“📚 Obsidian 资料”。
3. 选择仓库或项目目录并保存。
4. 在只读面板按人物、世界观或大纲浏览；Obsidian 修改后点击“刷新”。

目录未配置、已移动或不可访问时，面板会显示提示，但 SQLite 中的正文和原有模块仍可正常加载和使用。每个小说项目独立保存自己的目录，快速切换项目不会复用上一个项目的资料。

## AI 上下文

读取到的资料会用于 AI 对话、写章、审稿和自动修订。每次最多注入约 3500 token，并限制单篇摘录长度，不会一次发送整个仓库。人物、世界观和长期大纲冲突时优先参考 Obsidian；正文事实、伏笔等运行期状态仍以 SQLite 为准。

## 导入策划工作台（单向）

除只读浏览与 AI 上下文外，本阶段支持把 Obsidian 里的总纲、分卷纲、章纲、人物和世界观**单向导入** hi-story 的策划工作台与原生人物/世界观列表。导入不修改 Obsidian 文件，也不把 hi-story 里的修改回写。

### 识别与文件对应

- 人物、世界观按目录识别：`人物/`、`世界观/` 下的 Markdown；自动跳过 `00 *导航.md`、`配角速查.md` 等导航/汇总文件。
- 大纲靠文件名与 frontmatter 识别：`章节细纲`/`章节`/`章纲` → 章纲；`完整大纲`/`全书总纲`/`总纲`/`全书` → 总纲；`大纲_卷N`/`分卷`/`卷纲`/`第N卷` → 分卷纲。也支持 frontmatter 的 `role` / `roles`。
- 无法自动分类的 Markdown 保留为「未分类」，可在预览里手动指定槽位并触发主进程重新解析。

### 支持的真实格式

作者真实笔记以**无 frontmatter、markdown 表格章纲、`[[wiki链接]]`、有序/无序列表**为主。导入解析按此实现：

- 总纲：`《完整大纲.md》` 的 blockquote 卖点、作品定位、三卷索引、伏笔总表。
- 分卷纲：`《大纲_卷N.md》` 的标题章范围、核心冲突、阶段拆解、卷末钩子、重点人物。
- 章纲：`《章节细纲.md》` 的表格（章/标题/核心事件/剧情推进/爽点/悬念/伏笔/场景/情绪），按卷标题分段归属。
- 人物：独立人物文件的身份与能力、性格层次、欲望与成长。
- 世界观：标题段落 + 列表，正文全文作为描述。

### 覆盖语义

- 策划三层（总纲/分卷/章纲）提供「保留 / 填空 / 替换 / 清空」四选一；锁定层默认禁止替换，需明确「解锁并替换」。替换上游必须同步替换或清空下游。
- 人物/世界观按归一化名称匹配：同名默认跳过，可勾选覆盖；覆盖原地更新并保留 hi-story 独有字段（如人物 `profileOutline`、世界观 `parentId`）。
- 无已确认故事方向时，导入总纲会自动构造一个「Obsidian 导入方案」接通策划流程。

### 已知限制

- 章纲表格的部分列（视角、开场处境、人物变化）无对应字段，导入后留空，作者补填后才能用部分 AI 生成功能。
- 导入层无来源身份：策划层只能保证同一输入重复替换得到相同结果，无法识别文件移动/改名。
- 解析采用固定资源上限：单文件 2 MiB、最多 500 个候选、总读取 50 MiB，超限跳过并提示。
