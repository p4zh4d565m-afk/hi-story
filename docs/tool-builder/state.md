# hi-story 项目状态

## 产品

hi-story 是面向长篇小说创作的本地 Electron 工作台。当前核心链路包括策划、章纲、正文、AI 辅助、章节摘要、叙事事实、伏笔和本地参考检索。

## 已确认方向

- 保留 SQLite 作为正文、章节历史和运行时结构化状态的存储。
- 人物、世界观和长期大纲未来可由 Obsidian 主存，但在读取、迁移和回归链路完成前不删除 hi-story 现有模块。
- 下一阶段优先统一故事事实来源，并建立“AI 提议、作者确认、事务写入、下一章复用”的创作闭环。

## 当前进度

- 当前开发分支：`feature/skill-engine`。
- 策划工作台已覆盖故事方向、总纲、分卷纲、章纲及正文入口。
- 维护修复已覆盖 preload 监听释放、启动时保留有效语义索引，以及策划/写作切换时保留待保存正文。
- 章节保存失败会按章节保留待保存正文、明确显示等待重试，支持最多 2 次自动重试和手动立即重试；切章返回仍恢复草稿，成功落库后才清除。
- 项目切换加载已按“项目 ID + 请求代次”隔离；章节、大纲、人物、世界观、关系整组成功后原子提交，旧项目迟到或失败的结果不会写入当前状态，独立策划/素材/伏笔/角色关联加载同样校验当前项目。
- 详细维护发现见 `docs/maintenance-review-2026-09-07.md`。

## 后续优先项

1. 确定 Obsidian 与 SQLite 的数据归属、Markdown 模板和单向读取协议。
2. 将 AI 对话和创作决定从 localStorage 迁入 SQLite。
