## 先搞懂「时间快照」是什么

一句话：**AI 写第 N 章时，只能看到「第 N 章之前」发生的剧情，不能看到「第 N 章之后」才发生的事。**

举例：

- 主角在**第 30 章**才捡到一把宝剑 → 写**第 20 章**时，AI 不该让主角掏出这把剑（第 20 章时剑还没出现）。
- 一个伏笔在**第 80 章**才揭晓 → 审**第 50 章**时，这个伏笔应该还是「没揭晓」。

这个「只看到过去、不看到未来」的机制，代码里叫 as-of（时间快照）。

## 这次要测什么

以前有个 bug：时间快照加载失败时，程序会**偷偷退回「把全书最新状态一股脑喂给 AI」**——等于把第 21 章之后的事又泄露给第 20 章，串章问题回来。

修复后的正确行为：

- **写章、审稿**：拿不到时间快照 → **直接停下来报错**，不能继续生成。
- **普通对话**：拿不到时间快照 → 对话**能继续发**，但 AI「失忆」（不知道剧情），也**不能**偷偷用全书最新状态。

## 第 3 步：测「AI 对话」（哨兵事实对照法）

> ⚠️ 为什么用「哨兵事实」：第 3 步和前两步不一样——写章/审稿是「必须基于剧情」所以失败就停；对话允许在「不知道剧情」时继续聊，但绝不能「用错剧情」。所以**对话不报错是正常的**。
>
> 但「AI 是否恰好提到剧情」是主观判断，AI 可能因为措辞巧合没提到、也可能从正文/角色卡/世界观/大纲（这些是设计内允许注入、不经过 as-of 的部分）里看到剧情，导致误判。所以要插入一条**只存在于事实库、别处绝无**的哨兵事实，让「AI 是否带剧情」变成可判定的二元结果。

### 3.0 哨兵事实（已就绪）

测试项目「我有一个妹妹」已插入哨兵事实：主角「米尘」在第一章结尾捡到一枚刻着 **「玄霜铁令」** 的青铜令牌（event 类型，挂在第一章）。

判据成立的前提：「玄霜铁令」这个词在**正文、角色卡、世界观、大纲**里全部 0 匹配，唯一来源就是 `story_facts` 事实库。所以：

- **AI 能说出「玄霜铁令」** = 它读到了 as-of 事实层 = 带剧情。
- **AI 说不出「玄霜铁令」** = 它没读到 as-of 事实层 = 失忆。

### 3.1 正常基线（不注入 mock）

在 AI 对话里问：「米尘在第一章结尾捡到了什么信物？」

**应该看到** ✅：
- AI 能答出「玄霜铁令」（读到了 as-of 事实层）。

**不该看到** ❌：
- AI 答不出、或说「不知道 / 没这回事」。

### 3.2 失败态（注入 mock）

注入 mock 后，问**同样的问题**：「米尘在第一章结尾捡到了什么信物？」

**应该看到** ✅：
- 对话**能发出去**（不报错），但 AI **说不出「玄霜铁令」**——它失忆了，因为拿不到 as-of 事实层。

**不该看到** ❌：
- AI 仍能答出「玄霜铁令」（说明偷偷用了全书最新状态，bug 没修好）。

### 3.3 判定标准（二元）

「AI 能否答出玄霜铁令」是唯一判据：

- 3.1 正常基线：**必须答得出**。
- 3.2 失败态：**必须答不出**。

两者都满足，第 3 步才算真正通过。只满足其中一个、或两个都答得出/答不出，都算没通过。

### 第 3 步「对话失忆」的哨兵对照验证

复审指出原判据无效：测试项目事实库为空，AI 无论成败都看不到任何 story_facts，「失忆」与「正常」无法区分。据此升级为哨兵对照法：

1. 插入两条哨兵事实（event 类型，唯一来源 `story_facts`，正文/角色卡/世界观/大纲/对话历史全 0 匹配）：
   - 「玄霜铁令」：主角「米尘」第一章结尾捡到的青铜令牌。
   - 「赤阳火种」：陈城第二章末从拍卖行竞得的奇物。
2. **正常基线（无 mock）**：选中第二章，问「陈城在第二章末尾从拍卖行得到了什么？」→ AI 答出「赤阳火种」。✅
3. **失败态（注入 mock）**：问同样问题 → 对话能发、不报错，AI 答的是编造的「檀木匣子」，**没答出「赤阳火种」**（「檀木匣子」经查正文/事实库均 0 匹配，是纯脑补）。✅

判定逻辑：正常态已用编译后的真实代码确定性验证「选中第二章必注入赤阳火种」；失败态 AI 答不出 → 证明 as-of 确实失败、对话失忆通过。

### 复测注意事项（含两个坑）

- **旧 `dist/main` 缺叙事时间 IPC handler 会误判「通过」**：渲染端 catch 吞掉 invoke 异常，显示同名「加载失败」。复测前务必重新 `tsc -p tsconfig.main.json` 编译，且确认 `dist/main/main/ipc/narrative-time.ipc.js` 里确实带 mock 行。
- **必须完全退出 app 再重启**：编译 dist 只改磁盘文件，运行中的 Electron 进程内存里还是旧代码；不重启，mock 不会生效。
- **对话历史污染**：AI 对话历史跨章节共享且当前不可删除，A 段答过的哨兵词会留在历史里被 B 段照抄。复测时须用**历史里不存在的新哨兵词**（如本例的「赤阳火种」），否则无法区分「读到事实」还是「抄历史」。
